# Local Ollama coding assistant

Restart Light Table with the existing launcher. Open a project, choose **Assistant â†’ Chat**, then choose an installed local model in the chat panel. The choice is remembered. Ollama must be running at `http://127.0.0.1:11434`; **Assistant â†’ Refresh models** reconnects after an unavailable service.

The right dock has resizable **Chat / Activity** tabs. Code and the running program remain in the main workspace. Existing execution results, error links, watches and REPL information remain in Activity. Panel actions are in the native Assistant menu: New chat, Attach files, Attach selected code, Pause, Resume, Stop, Undo assistant edits and Settings. A visible **Stop** button appears beside Send while a prompt is running, including model loading and summarization. **Ctrl+Alt+.** also stops the assistant. Enter sends; Shift+Enter inserts a newline. Stop preserves an unsent draft and shows Stopping while owned work is being cleaned up.

The assistant runs with **Full Access**, using the Windows account's file and terminal permissions. Commands default to the conversation's project directory; explicit other paths are supported. Source files are edited with file tools and journaled before saving. Terminal commands have separate receipts, including output, actual exit codes and process-family memory accounting. Their arbitrary filesystem or external side effects are not reversed by Undo assistant edits.

One run can work until it finishes or is stopped, with no overall duration or tool-call limit. A message sent while it works steers it between steps. Pause prevents new actions at a safe boundary; an already running foreground command can finish. Stop aborts generation and terminates assistant-owned commands, servers and private previews. Manually started programs, servers, previews and the Ollama service retain their ownership. Missing required information and three identical failures without progress pause the run. Repeated unchanged file reads, directory listings or searches also warn and then pause after three observations without new information. Actual edits, new observations and steering allow progress; distinct file ranges and changed source are tracked separately.

The model receives the active project, selected code, an active-source excerpt, draft buffers, named buffer identities and attached source. File reads and searches use unsaved buffers when available. Existing files must be read before writing, renaming or deleting. Disk hashes and canonical document revisions reject stale changes. Linked and partial views share the same full document, history and save state. Save behavior runs through the original editor, and save failures retain dirty source. Undo restores a run's recorded file changes only when doing so will preserve subsequent user changes.

An assistant-created project starts empty for AI scaffolding. The normal File â†’ New project action still creates its JavaScript starter. Captured HTML/JavaScript previews update from unsaved buffers; development-server previews use the assistant's own background process and its actual loopback connection. DOM, console, errors and screenshots come from the running native view. Compatible updates preserve state; other edits can restart the program.

Automatic updates continue afterward. For a development-server preview, Run reloads the page using the existing server. It does not send a model prompt or save editor files.

Settings start with a **65,536-token context** and model thinking disabled. Click the context count in Chat, or open **Assistant â†’ Settings**, to change it. Presets are 8K, 16K, 32K, 64K, 128K and 256K; the custom field accepts exact integer values from 2,048 to 262,144 tokens. Save updates the count, remembers the choice after restart and uses it on the next model request. Cancel keeps the saved value. Older work is summarized while retaining the goal, latest user request, changed files, remaining work and command receipts. Recent complete assistant/tool exchanges are retained through compaction, including current file contents. File reads are sized to fit the configured context and return `next_read` with accurate line/column positions when more source remains; the canonical file hash still covers the whole source. Conversations, journals and checkpoints are saved under `source/.revival/proof-user/assistant`, indexed by project; test runs use `test-user/assistant`. Restarted unfinished work is paused and no unfinished command is replayed automatically.

The Ollama service and its loaded model are outside these quotas. Captured previews retain the existing 15-minute program session and per-program execution/resource protections; these are separate from the assistant run's duration. Restarting a preview continues the assistant's work.
