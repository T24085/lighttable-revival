# Local Ollama coding assistant

Restart Light Table with the existing launcher. Open a project, choose **Assistant â†’ Chat**, then choose an installed local model in the chat panel. The choice is remembered. Ollama must be running at `http://127.0.0.1:11434`; **Assistant â†’ Refresh models** reconnects after an unavailable service.

The right dock has resizable **Chat / Activity** tabs. Code and the running program remain in the main workspace. Existing execution results, error links, watches and REPL information remain in Activity. Panel actions are in the native Assistant menu: New chat, Attach files, Attach selected code, Pause, Resume, Stop, Undo assistant edits and Settings. A visible **Stop** button appears beside Send while a prompt is running, including model loading and summarization. **Ctrl+Alt+.** also stops the assistant. Enter sends; Shift+Enter inserts a newline. Stop preserves an unsent draft and shows Stopping while owned work is being cleaned up.

The assistant runs with **Full Access**, using the Windows account's file and terminal permissions. Commands default to the conversation's project directory; explicit other paths are supported. Source files are edited with file tools and journaled before saving. Terminal commands have separate receipts, including output, actual exit codes and process-family memory accounting. Their arbitrary filesystem or external side effects are not reversed by Undo assistant edits.

Conversations and settings live in `%LOCALAPPDATA%/LightTableRevival/profiles/<workspace-id>/assistant`. On first launch after this update, existing history is copied from the source folder without deleting the originals. Keeping checkpoints outside OneDrive avoids cloud-sync file replacement conflicts. Atomic saves retry brief sharing violations while retaining the previous complete checkpoint; persistent failures pause the task.

Assistant tasks require automatic local review. Coding and review together have the existing thirty-minute budget and at most three correction rounds. The background reviewer is selected automatically from installed compatible local decision models; there is no per-task Off switch. A message sent while it works steers it between steps. Pause prevents new actions at a safe boundary; an already running foreground command can finish. Stop aborts generation and terminates assistant-owned commands, servers and private previews. Manually started programs, servers, previews and the Ollama service retain their ownership. Missing required information and three identical failures without progress pause the run. Repeated unchanged file reads, directory listings or searches also warn and then pause after three observations without new information. Actual edits, new observations and steering allow progress; distinct file ranges and changed source are tracked separately.

The model receives the active project, selected code, an active-source excerpt, draft buffers, named buffer identities and attached source. File reads and searches use unsaved buffers when available. Existing files must be read before writing, renaming or deleting. Disk hashes and canonical document revisions reject stale changes. Linked and partial views share the same full document, history and save state. Save behavior runs through the original editor, and save failures retain dirty source. Undo restores a run's recorded file changes only when doing so will preserve subsequent user changes.

File → New project creates a folder with exactly one starting file, defaulting to `index.html`. Choose the starting filename and file type in the dialog. HTML starts with a minimal document; other types start blank. File → New file, Ctrl+N, New file in project, and the workspace folder's New file action use the same type picker, including Python, JavaScript, TypeScript, HTML and custom extensions. Cancelling creates nothing; existing files are never overwritten.

Failed file actions retain their intended effect in the checkpoint. A later journaled write can resolve a failed edit when it saves the intended replacement; an unrelated file, unrelated rewrite, different rename destination or ordinary write after a failed delete cannot erase that failure. Intent survives restart and Resume. Read-before-edit, stale-source rejection and conflict-safe Undo remain active.

The assistant's `create_project` tool supports an empty project and a configured `vite-react-tailwind` starter for requested framework projects. The latter includes React, TypeScript, Vite, Tailwind v4's Vite plugin, a stylesheet import and build/dev scripts; its source files are journaled. With Automatic live view enabled, creating or reopening a Vite project installs missing dependencies and opens its running `dev` server beside the code after the existing project-execution permission is allowed. The preview's Run button retries setup failures or reloads the existing server; Pause releases an automatically started server. Source changes reach Vite on Save. Automatic setup waits while the coding assistant works or its own preview is displayed, avoiding competing startup. The assistant can also install/build/start its own server through journaled tools. Captured HTML/JavaScript previews update from unsaved buffers. DOM, console, errors and screenshots come from the running native view. Compatible updates preserve state; other edits can restart the program. See [automatic preview verification](AUTO-PREVIEW-2026-10-06.md).

Assistant commands use non-interactive PowerShell. Vite CLI scaffolding requires `--no-interactive` and an explicit template in an empty directory. A cancelled scaffold is reported as a failure even when the CLI exits with code 0. Tailwind setup guidance follows the installed major version; v4 uses `@tailwindcss/vite` and a CSS import rather than `tailwindcss init`. PowerShell and native-command failures stop the command batch before a later success can hide them. Repeated setup failures with different flags count toward the existing three-failure pause. Empty model replies are retried twice, then paused rather than marked complete. See [the chat setup repair and actual Vite/Tailwind validation](CHAT-SETUP-REPAIR-2026-10-06.md).

Automatic updates continue afterward. For a development-server preview, Run reloads the page using the existing server. It does not send a model prompt or save editor files.

Settings start with a **65,536-token context** and model thinking disabled. Click the context count in Chat, or open **Assistant â†’ Settings**, to change it. Presets are 8K, 16K, 32K, 64K, 128K and 256K; the custom field accepts exact integer values from 2,048 to 262,144 tokens. Save updates the count, remembers the choice after restart and uses it on the next model request. Cancel keeps the saved value. Every coding and summarization request explicitly sends `options.num_ctx`, overriding Ollamaâ€™s default for that request. Ornith 1.5 9B reports a 262,144-token model maximum in the installed `/api/show` metadata. Older work is summarized while retaining the goal, latest user request, changed files, remaining work and command receipts. Recent complete assistant/tool exchanges are retained through compaction, including current file contents. File reads are sized to fit the configured context and return `next_read` with accurate line/column positions when more source remains; the canonical file hash still covers the whole source. Conversations, journals and checkpoints are saved under `%LOCALAPPDATA%/LightTableRevival/profiles/<workspace-id>/assistant`, indexed by project. Existing history is copied there on first launch while preserving its original files; isolated tests use `.revival/test-user/assistant`. Restarted unfinished work is paused and no unfinished command is replayed automatically.

Existing execution memory allowances remain: 1 GiB for command families and browser renderers, with the separate JVM allowance retained. The Ollama service and its loaded model are outside these quotas. Captured previews retain the existing 15-minute program session and per-program execution/resource protections; these are separate from the assistant run's duration. Restarting a preview continues the assistant's work.
