# Local preview reviewers

Restart with the existing Light Table launcher. Reviewers have their own remembered model selector beside either live preview and in **Assistant → Settings**. The coding model selection remains independent.

Only installed local models advertising Ollama's `decision` capability are eligible. A `vision` capability or installed projector metadata identifying a vision encoder enables screenshots. Ollama 0.35.1 can return only `decision` for Clef while exposing its vision weights through `projector_info`; Light Table recognizes that metadata without guessing from model names. Ollama must support `/v1/systemone`; Clef requires 0.35.1 or later. Models are never downloaded automatically. For example, install explicitly with `ollama pull clef-flash:9b-q8_0` or the smaller text-only `ollama pull tev1:4b-q4_K_M`, then use **Assistant → Refresh models**.

**Review preview** assesses the live program at 1280 × 800 desktop and 390 × 844 mobile without changing source. It collects DOM/control bounds, overflow, console errors, applicable test receipts and five-second browser frame/long-task samples. Image-capable reviewers also receive actual PNG pixels. The view returns to its original dimensions and scroll position after sampling, including Stop and failure paths.

Text-only models receive compact structured evidence and never receive images. Their reports say that image appearance was not assessed. Explicit requests for screenshot verification remain uncertain without an image reviewer. These are exact CSS viewport checks, rather than phone hardware emulation. Frame measurements describe browser rendering, not application-specific FPS or independently verified end-user responsiveness. Suspected frame-time regressions above 20% receive another sample and pause correction if reproduced.

Development-server captures retain separate fingerprints for served responses and project source files, so transformed HTML or TypeScript can be checked against current editor and disk contents. Source changes invalidate a review. If a server's responses cannot be bound to project files, automatic correction remains unverified and pauses.

Reviewed test commands record source fingerprints before and after execution. An edit during testing invalidates the receipt, even when the command exits successfully. New chat instructions pause a reviewed task; Resume locks the new request as fresh criteria.

Reviewer probabilities are advisory. Selection probabilities below the provisional 0.85 threshold pause correction. Observable runtime errors, failed assertions and applicable failed or stale tests override favorable answers. No performed interaction checks means that browser interaction behavior is explicitly unverified; explicitly required behavior pauses without passing assertions at both sizes. The coding assistant can use `check_preview` to execute recorded JavaScript assertions at either viewport; assertions return `{passed:boolean,details:string}` and are bound to the preview source revision.

## Enable automatic correction

Every new reviewer/digest is **Untested**. Manual Review works for testing. **Assistant → Settings → Validate reviewer** runs twelve fixed native cases and three complete desktop/mobile measurement/review cycles. Text reviewers must also recognize two insufficient-evidence cases: missing interaction receipts and unspecified acceptance requirements. Passing requires at least ten correct fixed cases, detection of all missing-control defects, no defect classification on clean cases, correct uncertainty judgments at both sizes, and each runtime cycle within five minutes. Receipts are tied to model digest, image support and reviewer protocol version. Updating weights invalidates qualification. Failed or cancelled validation keeps automatic correction disabled.

Receipts record request latency, sampled model RAM/VRAM, host free RAM and live-preview response times during inference. The time until the runner first appears is a loading estimate that includes scheduling and polling. System One does not report pure weight-loading time, and a fast request can finish before its runner is sampled; unavailable measurements stay explicit.

After qualification, **Improve preview** corrects the latest request or clear defects. The per-task **Review and improve this task** checkbox adds the same checkpoint to ordinary assistant work. These modes allow three correction rounds or thirty minutes, including loading and command execution. They preserve the design unless redesign is requested and use the existing source journal, stale-edit guards, save flow and Undo.

Pause prevents the next action at a safe boundary; Stop cancels inference/sampling and owned work. Repeated findings, conflicting/uncertain evidence, stale source, resource failures and exhausted limits pause the run with an explanation. Resume begins a new bounded session and recaptures evidence. Interrupted work reopens paused after restart, with no automatic replay.

Coding and review requests run sequentially. The selected coding model is unloaded before capture and measurement, so baseline and recheck samples use matching model residency conditions. The reviewer stays loaded across the two viewport requests and is released afterward, including errors. Temporary reviewer screenshots remain in memory and never enter the conversation JSON; reports retain source identities, findings, probabilities and measurements. Closing/stopping a review releases those images. Manually owned previews retain their ownership.

## Verification

Run `pwsh -NoProfile -File script/revival-reviewer-test.ps1` for deterministic protocol/controller tests and a serialized native Electron proof. This proof uses simulated inference with actual pixels, journaled edits, Node tests and browser controls; it is not real-model accuracy evidence. Run `script/revival-test.ps1` for the complete existing editor/runtime regression. After installing weights, run real-model qualification before enabling automatic correction.

For isolated real-weight qualification, run `& ./script/revival-reviewer-real-test.ps1 -Models @('tev1:4b','clef-flash:9b')` in PowerShell, using your installed tags. It uses the production evidence collector and reviewer rubric, actual native browser fixtures, and a live preview responsiveness probe. Each model has a thirty-minute limit and each request has the existing five-minute limit. It restores test qualification state and writes `.revival/reviewer-real-result.json`; the normal app's selections, conversations and qualification receipts are unchanged. Use **Validate reviewer** in the app to store a qualification for normal use.

On 2026-10-06 the installed Q8_0 Tev1 completed three cycles in about seventeen seconds each and classified ten of twelve cases correctly, but did not detect every seeded missing control. Installed Q8_0 Clef reached the first request deadline during loading. Both remain **Untested**, with manual review available and automatic correction disabled. These are local results for the installed tags and hardware; see [the measured results](TEST-RESULTS.md).
