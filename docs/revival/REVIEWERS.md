# Local preview reviewers

Review is automatic and required for assistant tasks. The per-task reviewer selector and Off switch have been removed. Light Table retains an available remembered local decision model or automatically chooses the smallest eligible installed model. Coding and reviewer models stay independent. If no compatible local reviewer is installed, Send preserves the draft and explains the missing dependency; models are never downloaded automatically. Normal coding settings and conversation history are retained.

Review runs in the background. The existing status and expandable report record what happened; the reviewer does not ask conversational follow-up questions. Uncertain or failed checks still pause rather than report success. Validation remains an optional diagnostic for installed weights. The initial evidence pipeline covers browser and development-server previews; tasks without a supported preview can pause with an explicit verification limitation.

Only installed local models advertising Ollama's `decision` capability are eligible. Clef support is temporarily removed: its named models and renamed weights identified by Clef metadata are excluded from the coding selector and automatic reviewer discovery. Saved Clef selections reset, and direct requests are refused. The installed `tev1:4b` is available. Use **Assistant → Refresh models** after restarting. Models are never downloaded automatically. A `vision` capability or installed projector metadata identifying a vision encoder enables screenshots for other eligible models. Ollama must support `/v1/systemone`.

Automatic review assesses the live program at 1280 × 800 desktop and 390 × 844 mobile before correction. It collects DOM/control bounds, overflow, console errors, applicable test receipts and five-second browser frame/long-task samples. Image-capable reviewers also receive actual PNG pixels. The view returns to its original dimensions and scroll position after sampling, including Stop and failure paths.

Text-only models receive compact structured evidence and never receive images. Their reports say that image appearance was not assessed. Explicit requests for screenshot verification remain uncertain without an image reviewer. These are exact CSS viewport checks, rather than phone hardware emulation. Frame measurements describe browser rendering, not application-specific FPS or independently verified end-user responsiveness. Suspected frame-time regressions above 20% receive another sample and pause correction if reproduced.

Development-server captures retain separate fingerprints for served responses and project source files, so transformed HTML or TypeScript can be checked against current editor and disk contents. Source changes invalidate a review. If a server's responses cannot be bound to project files, automatic correction remains unverified and pauses.

Reviewed foreground test commands record a project-source fingerprint before and after execution, independently of preview startup. Each receipt retains its own revision and project root. All applicable commands must have completed successfully against the current saved files; a newer passing command cannot validate an older stale receipt. Tests, configuration and source files are included; generated dependency/build folders and assistant history are excluded. Unsaved buffers, linked entries or incomplete inventories remain unverified. Inventories are bounded to 2,048 entries, 16 MiB per file and 64 MiB total. Existing receipts without source binding require a fresh test run. New chat instructions pause a reviewed task; Resume locks a new request as fresh criteria.

The coding model can declare up to eight concise acceptance checks through `set_review_criteria` before changing files. Required controls use CSS selectors; interaction requirements have stable IDs and must each receive a passing `check_preview` receipt with the matching `check_id` at both sizes. Missing or hidden controls fail deterministic checks even when the model classifies the layout as clean. Missing interaction receipts remain uncertain. Declared criteria lock after declaration and persist across Resume; a new user request starts fresh criteria. The original request remains in the report, while check descriptions contain product requirements rather than tool instructions. Questions use the existing `ask_user` flow only for missing requirements.

Reviewer probabilities are advisory. Selection probabilities below the provisional 0.85 threshold pause correction. Observable runtime errors, failed assertions and applicable failed or stale tests override favorable answers. No performed interaction checks means that browser interaction behavior is explicitly unverified; explicitly required behavior pauses without passing assertions at both sizes. The coding assistant can use `check_preview` to execute recorded JavaScript assertions at either viewport; assertions return `{passed:boolean,details:string}` and are bound to the preview source revision.

## Optional reviewer validation

Every new reviewer/digest is **Untested** and remains usable. The optional diagnostic runner tests twelve fixed native cases and three complete desktop/mobile measurement/review cycles. Text reviewers must also recognize two insufficient-evidence cases: missing interaction receipts and unspecified acceptance requirements. Passing requires at least ten correct fixed cases, detection of all missing-control defects, no defect classification on clean cases, correct uncertainty judgments at both sizes, and each runtime cycle within five minutes. Receipts are tied to model digest, image support and reviewer protocol version. Updating weights invalidates that diagnostic result. Failed or cancelled validation leaves the model Untested and does not disable task review or improvement.

Receipts record request latency, sampled model RAM/VRAM, host free RAM and live-preview response times during inference. The time until the runner first appears is a loading estimate that includes scheduling and polling. System One does not report pure weight-loading time, and a fast request can finish before its runner is sampled; unavailable measurements stay explicit.

Automatic improvement corrects the latest request or clear defects. Ordinary assistant work enters the checkpoint automatically. These modes allow three correction rounds or thirty minutes, including loading and command execution. They preserve the design unless redesign is requested and use the existing source journal, stale-edit guards, save flow and Undo.

Pause prevents the next action at a safe boundary; Stop cancels inference/sampling and owned work. Repeated findings, conflicting/uncertain evidence, stale source, resource failures and exhausted limits pause the run with an explanation. Resume begins a new bounded session and recaptures evidence. Interrupted work reopens paused after restart, with no automatic replay.

Coding and review requests run sequentially. The selected coding model is unloaded before capture and measurement, so baseline and recheck samples use matching model residency conditions. The reviewer stays loaded across the two viewport requests and is released afterward, including errors. Temporary reviewer screenshots remain in memory and never enter the conversation JSON; reports retain source identities, findings, probabilities and measurements. Closing/stopping a review releases those images. Manually owned previews retain their ownership.

## Verification

Run `pwsh -NoProfile -File script/revival-reviewer-test.ps1` for deterministic protocol/controller tests and serialized native Electron proofs, including mandatory Send with an automatically selected Untested reviewer. These proofs use simulated inference with actual pixels, journaled edits, Node tests and browser controls; they are not real-model accuracy evidence. Run `script/revival-test.ps1` for the complete existing editor/runtime regression. Optional real-model validation measures an installed reviewer's diagnostic results.

For isolated real-weight qualification, run `& ./script/revival-reviewer-real-test.ps1 -Models @('tev1:4b')` in PowerShell, using your installed tags. It uses the production evidence collector and reviewer rubric, actual native browser fixtures, and a live preview responsiveness probe. Each model has a thirty-minute limit and each request has the existing five-minute limit. It restores test qualification state and writes `.revival/reviewer-real-result.json`; the normal app's selections, conversations and qualification receipts are unchanged.

An earlier Q8_0 Tev1 qualification completed three cycles in about seventeen seconds each and classified ten of twelve cases correctly, but did not detect every seeded missing control. It remains **Untested** with review and improvement available; validation is optional. Clef is now excluded. These are local results for the installed tags and hardware; see [the measured results](TEST-RESULTS.md).
